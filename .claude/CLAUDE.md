- 可能な限り日本語で回答すること

## 変更・実装のルール

- プログラムの変更・修正・実装を行う前に、必ず実行してよいか確認すること
- 許可を得てから変更・修正・実装を行うこと

## Gitに関するルール

- 「コミットメッセージを作成して」という指示は、メッセージの文面を作成するだけの意味であり、`git commit`の実行(コミットそのもの)は含まない。実際にコミットするのは、明示的に「コミットして」等の別の指示があった場合のみとする
- `git commit`・`git push`など履歴やリモートを変更する操作は、その都度明示的な許可を得てから実行すること

### コミットメッセージのルール

- 1行目は `<種別>: <要約>`。種別は英語 (feat / fix / docs など)、要約は日本語で「〜を追加」「〜を修正」の形にする
- 本文は日本語の箇条書きで、何を変えたかだけを1項目1行で書く。経緯や理由の説明は必要なときに括弧で短く添える程度にする
- 冗長な言い回しは避け、簡潔に書く
  - 悪い例: 「Python のバージョン判定が 3.5〜3.9 しか通さず、3.10 以降で失敗していたため、正規表現を修正」
  - 良い例: 「prereq-build.mk: Python のバージョン判定正規表現を 3.10〜3.19 も許可するよう修正」
- 変更は目的ごとにコミットを分ける
- コミットする前にメッセージの案をユーザーに見せ、了承を得る

例:
fix: Ubuntu 22.04 でのビルドエラーを修正

- prereq-build.mk: Python のバージョン判定正規表現を 3.10〜3.19 も許可するよう修正
- m4: 1.4.19 に更新 (glibc 2.34 以降の SIGSTKSZ エラー対策)、旧パッチ2つを削除
